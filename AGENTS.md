# AGENTS.md — Конституция репозитория и диспетчер контуров (v2.2)

 Инструкция для AI-агента (OpenAI Codex  OpenCode) Этот файл является обязательным регламентом работы в данном репозитории. Перед выполнением любой задачи ознакомься с правилами ниже, определи активный контур работы и загрузи указанный стартовый пакет документов.

## 1. Глобальные константы (действуют во всех контурах)

1. Единый стандарт Все решения подчиняются `docsENGINEERING_STANDARD.md` (v2.2).
2. Бизнес-фокус (Portfolio & ROI First) Проект создается как коммерческий B2B-кейс. Любая фича оценивается через измеримую пользу для собственника (экономия ФОТ, рост конверсии, скорость реакции, окупаемость)[cite 6]. Выдуманные цифры запрещены — статистика строится только на реальных логах БД и формулах из `docspassport.md`[cite 6].
3. Vendor-Agnostic & On-Premise Ready Система запускается на облачных API, но обязана переноситься на локальные модели (`Ollama`  `vLLM`  `LocalAI`) за 1–2 дня без переписывания бизнес-логики[cite 6]
    Все вызовы LLM и эмбеддингов идут через единый OpenAI-совместимый клиент (`BASE_URL`, `API_KEY`, `MODEL_NAME`) из `.env`[cite 6].
    Модели строго разделены на `FAST_LLM_MODEL`, `SMART_LLM_MODEL` и `EMBEDDING_MODEL` (открытые модели класса `BGE-M3`  `E5`)[cite 6].
    Интеграции с CRM (Bitrix24), БД и файлами изолируются через стандартизированные MCP-серверы и Skills[cite 6].
4. Архитектурная гигиена
    Глубокая модульность `core` (ядро), `modulesname` (изолированные плагины без прямых кросс-импортов), `apps` (тонкие интерфейсы без бизнес-логики), `ops` (эксплуатация и бенчмарки), `tests` (зеркальные тесты), `infra` (запуск)[cite 6].
    Сетевая привязка локальных сервисов строго по `127.0.0.1port` (вместо `localhost`)[cite 6].

## 2. Маршрутизация контуров (Ролевая модель)

Определи активную роль по тегу в начале промпта пользователя (`@arch`, `@dev`, `@ops`, `@biz`) или по смыслу задачи и строго соблюдай границы своей роли

### 🏛 Контур 1 Архитектор (`@arch`)
 Стартовый контекст `docsENGINEERING_STANDARD.md` + `docsstatus.md` + `docscontracts.md`[cite 6].
 Задачи Проектирование модульной структуры, утверждение Pydantic-схем, таблиц БД и MCP-контрактов в `docscontracts.md`, декомпозиция задач для Разработчика, архитектурное ревью[cite 6].
 Ограничения Не пишет продакшн-код напрямую вместо проектирования контрактов[cite 6].

### 💻 Контур 2 Разработчик (`@dev` — роль по умолчанию при запросах на код)
 Стартовый контекст `docsstatus.md` + `docscontracts.md` (+ `docsprompts_registry.md` при работе с промптами)[cite 6].
 Задачи
  1. Написание чистого типизированного кода строго в рамках `docscontracts.md`[cite 6].
  2. Вынос всех промптов из Python-кода в версионируемые YAMLMD файлы с загрузкой через `LLM Gateway`[cite 6].
  3. Строгая валидация DTO (`model_config = ConfigDict(extra=forbid)`), принудительный `json_object`, очистка markdown-оберток и отсечение лишних ключей LLM[cite 6].
  4. Реализация Guardrails (при нехватке данных в RAGпрайсе обязателен флаг `need_human true`, запрет на выдумывание условий)[cite 6].
  5. Встраивание телеметрии в каждую транзакцию (`request_id`, `processing_time_sec`, `tokens_in`, `tokens_out`, `cost_rub`, `ab_variant`, `mode`, `channel`, `is_after_hours`, `need_human`, `saved_minutes`)[cite 6].
  6. Покрытие логики юнит- и интеграционными тестами в `tests` с моками платных API[cite 6].

### ⚙️ Контур 3 Операционщик  QA (`@ops`, `@qa`)
 Стартовый контекст `docsoperations.md` + `docsstatus.md` + `opsrunners`[cite 6].
 Задачи
  1. Preflight-проверки инфраструктуры (`docker-compose ps` или порты `127.0.0.1`), проверка `.env`[cite 6].
  2. Запуск e2e smoke-тестов (`dry-run` и `--live-llm`)[cite 6].
  3. Генерация и прогон «грязных» бенчмарк-датасетов (50–100 кейсов шум, опечатки, провокации вне базы знаний) для проверки Guardrails на галлюцинации, AB-сравнения промптов и наполнения БД логов реальными цифрами для графиков ROI[cite 6].
  4. Замер фактической экономики (время цикла, токены, стоимость в ₽, процент эскалаций)[cite 6].
 ЖЕЛЕЗНОЕ ПРАВИЛО В контуре `@ops`  `@qa` правка исходного кода (`core`, `modules`, `apps`) СТРОГО ЗАПРЕЩЕНА[cite 6]. Все найденные баги, галлюцинации и нестыковки записываются в секцию `## Найденные проблемы` файла `docsstatus.md` для передачи в `@dev`[cite 6].

### 📊 Контур 4 Бизнес-аналитик  Продакт (`@biz`, `@ba`, `@pm`, `@pack`)
 Стартовый контекст `docsstatus.md` + `docspassport.md` + `docsplaybooks`[cite 6].
 Задачи
  1. Оцифровка процесса «Точка А vs Точка Б», расчет юнит-экономики и формул ROI в `docspassport.md`[cite 6].
  2. Проектирование UX демо-стенда (вкладка `Live Demo` + вкладка `Executive ROI-дашборд` с графиками по логам БД и ползунками юнит-экономики для клиента)[cite 6].
  3. Написание прикладных плейбуков (`docsplaybooksslug.md`) и финальная упаковка проекта в продающий `README.md` и веб-презентацию `docspresentationindex.html`[cite 6].
 Ограничения Не меняет архитектуру `core` и `modules` напрямую — формирует постановки для `@arch` и `@ops`[cite 6].

## 3. Обязательный протокол завершения задачи (Definition of Done)

Перед тем как отчитаться пользователю о завершении любого шага
1. Проверки (`@dev`) Запусти `pytest`, `ruff check .`, `mypy .` и убедись, что все проверки зеленые (без реальных платных вызовов API в тестах)[cite 6].
2. Прогоны (`@ops`) Выполни smokeбенчмарк-раннер из `opsrunners` и зафиксируй фактические метрики[cite 6].
3. Реестр промптов При любом изменении текста или логики промптов обнови версию и AB-тег в `docsprompts_registry.md`[cite 6].
4. Срез состояния (`docsstatus.md`) Перезапиши (in-place update, строго 80–130 строк) актуальное состояние в `docsstatus.md`[cite 6]
    обнови только секцию своего модуляконтура[cite 6];
    удали выполненные задачи из бэклога и закрытые баги из `## Найденные проблемы`[cite 6];
    сохрани не более 5 последних вех (FIFO)[cite 6];
    обнови счетчик тестов, активные порты `127.0.0.1` и фактические бизнес-метрики (время цикла, себестоимость, точность)[cite 6].
